How This Testing Works

You run all prompts through Codex CLI — Relay never intercepts your terminal. In the baseline phase, Codex has no context help. In the Relay phase, Codex connects to relay mcp over stdio, which feeds it deterministic project context automatically. Both phases produce Codex session files that you upload to the Compare Page — no manual metric recording required.

The test project is AgentFlow. You run the same 5 prompts in both phases and let the comparison page calculate token reduction, response quality, and the verdict.

Setup Before You Start
01 Build RelayAI ▶

Install dependencies and compile the CLI. You only need to do this once per code change.

terminal — RelayAI repo
cd /path/to/RelayAI
pnpm install
pnpm build
ℹ️ Verify the build succeeded: node packages/cli/dist/index.js --help should print the Relay command list.
02 Clone & build the test project (AgentFlow) ▶

AgentFlow is the project you'll be asking Codex questions about. It must build cleanly before testing starts.

terminal
git clone https://github.com/mrwalker511/AgentFlow.git
cd AgentFlow
npm install
npm run build
npm test
⚠️ If npm test fails, fix the project before continuing. You need a clean baseline.
03 Record the baseline git SHA ▶

Save this SHA — Relay will anchor its session diff to it so follow-up prompts only contain what changed.

terminal — AgentFlow
git rev-parse HEAD
📋 Save the SHA output somewhere handy — you'll reference it in Step 9.

07 Save the Codex baseline session file ▶

Codex automatically saves your session to ~/.codex/sessions/. Find the most recent file, copy it, and rename it so you can tell it apart later.

terminal
# Find the latest session file
ls -lt ~/.codex/sessions/ | head -5

# Copy and rename it
cp ~/.codex/sessions/<latest-uuid>.json ~/relay-test-baseline.json
📁 If Codex stores sessions elsewhere on your system, check codex --help or your Codex config for the sessions directory path.
Phase 2 Relay-Enabled — Codex + Relay MCP
ℹ️ You'll still use Codex CLI directly — but now Relay runs as an MCP server in the background. Codex automatically calls Relay tools to get deterministic project context before it answers. You type prompts in Codex exactly as before.
08 Initialize Relay in AgentFlow ▶

This creates the .relay/ directory and writes the default config. Run this once per project.

terminal — AgentFlow
cd /path/to/AgentFlow

# If relay is on your PATH:
relay init

# If using the local build directly:
node /path/to/RelayAI/packages/cli/dist/index.js init
09 Verify Relay health ▶

Run the doctor check. All items must pass before you continue.

terminal — AgentFlow
relay doctor
⚠️ Fix any errors relay doctor reports before moving on. A failing doctor means context will be incomplete.
10 Start the Relay session ▶

This anchors Relay's diff tracking to the current git SHA. The SHA printed should match the one you recorded in Step 3.

terminal — AgentFlow
relay session start
ℹ️ Relay prints the base SHA it anchored to. Confirm it matches your baseline SHA from Step 3.
11 Add Relay to Codex's MCP configuration ▶

Codex reads its MCP server list from ~/.codex/config.json (or your platform's equivalent). Add the relay entry below. When Codex starts, it will launch relay mcp as a subprocess over stdio.

~/.codex/config.json — add this block
{
  "mcpServers": {
    "relay": {
      "command": "relay",
      "args": ["mcp"]
    }
  }
}
ℹ️ If relay isn't on your PATH, replace "command": "relay" with "command": "node" and add the full path to args: ["args": ["/path/to/RelayAI/packages/cli/dist/index.js", "mcp"]].
⚠️ The Relay MCP server is read-only. It provides context to Codex but does not run GC, start sessions, or write files. You still run those relay commands yourself from the terminal.
12 Open a fresh Codex session (with Relay connected) ▶

Start Codex from the AgentFlow directory. Codex will automatically connect to the Relay MCP server. You should see Relay listed as an available tool in the Codex interface.

terminal — AgentFlow
cd /path/to/AgentFlow
codex
✅ You should see Relay MCP tools listed (get_prompt_payload, get_project_context, etc.) when Codex connects.
